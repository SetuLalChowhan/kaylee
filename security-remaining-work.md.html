2. CRITICAL (open)

R1. Preview token is a login token (was C1)

  • Where: controllers/ugc_campaign.controller.ts appendPreviewToken, middlewares/auth.middleware.ts
  • Problem: preview JWT is signed with ACCESS_TOKEN_SECRET, valid 30 days, has no userId, and authGuard accepts it. Prisma ignores where: { userId: undefined }, so list endpoints (/api/ugc-campaigns, /analytics, /api/invoice, dashboard stats, planner) can return all users' data. Anyone who passes OTP with their own email gets such a token.
  • Fix:
    1. Sign with PREVIEW_TOKEN_SECRET, payload { campaignId, type: "preview" }, expiry stays 30 days (owner decision, do not shorten).
    2. In authGuard, after verify, reject unless typeof decoded.userId === "string" && decoded.type !== "preview".
    3. Add requireUserId(req) (401 if not a non-empty string) and call it wherever a { userId } filter is built.
  • Residual risk (report): a 30-day preview token for a campaign remains valid for that campaign's media only, even after revoke. Recommend a shorter lifetime later.
  • Test: preview token against /api/invoice, /api/user/dashboard-stats, /api/ugc-campaigns/analytics returns 401.

R2. Download lock bypass (was C2)

  • Where: middlewares/download.middleware.ts
  • Problem: trusts spoofable Referer/Origin (includes() substring match), accepts any valid JWT, loose contains: filename lookup, feedback files unprotected.
  • Fix: rewrite the interceptor:
    1. Remove all Referer/Origin logic and debug logs.
    2. Find the record by exact URL in ugcMedia, ugcDocument, ugcFeedbackMessage.fileUrl. None found: 404.
    3. campaign.releaseFiles === true: serve.
    4. Else allow only (a) an access token whose user is the owner or admin, or (b) for media only, a preview token whose campaignId equals the file's campaign. Otherwise 403.
    5. Set X-Content-Type-Options: nosniff.
  • Residual risk (report, do not implement): locked media must still stream for preview, so a technical brand user could capture it. Full fix needs watermarked or low-res previews (product change).
  • Test: locked file with fake Referer: https://getstakd.co returns 403. Locked document with a preview token returns 403.

R3. SMTP password public (was C3)

  • Where: controllers/cms.controller.ts, routers/cms.route.ts, admin Settings.jsx
  • Fix:
    1. Public GET /api/cms excludes keys starting with smtp_ and email_from_.
    2. New GET /api/cms/admin (authGuard, adminGuard) returns all keys, with smtp_pass as "". Point only the admin Settings page at it.
    3. PUT /api/cms: ignore empty smtp_pass, validate keys /^[a-z0-9_]{1,64}$/, cap value length at 10,000.
  • Test: unauthenticated GET /api/cms has no smtp_*. Admin Settings still saves and mail still sends.

R4. Default admin and password (was C4)

  • Where: seeds/admin.seed.ts, user.controller.ts adminCreateUser
  • Fix: seed reads ADMIN_EMAIL/ADMIN_PASSWORD; if missing, skip and warn (never log the password). In adminCreateUser remove the "user123" fallback: no password given means generate a random one and send a reset email. Zod-validate email, names, and role in ["user","admin"].

R5. Arbitrary file deletion (was C5)

  • Where: user.controller.ts (updateProfile, deleteBrandLogo, cleanUserPhysicalFiles), utils/upload.util.ts
  • Fix: add safeUnlink(dbPath): path.resolve(UPLOAD_ROOT, ...) must start with UPLOAD_ROOT + path.sep, else do nothing. Replace every fs.unlinkSync(getAbsoluteUploadPath(...)) with it. In updateProfile accept client brandLogos entries only if they match ^uploads/brand-logos/[A-Za-z0-9._-]+$ and already exist in the user's stored list.
  • Test: brandLogos=["../../.env"] is rejected and the file survives.

R6. IDOR on creator child routes (was C6)

  • Where: ugc_campaign.controller.ts: updateDeliverable, deleteDeliverable, updateCampaignTask, deleteCampaignTask, deleteNote, deleteMedia, replaceMedia, deleteDocument, createFeedback (mediaId).
  • Problem: access is checked on :campaignId only; delete({ where: { id } }) ignores it.
  • Fix: findFirst({ where: { id, campaignId } }), 404 if missing. Writes use updateMany/deleteMany with { id, campaignId }. Verify mediaId in createFeedback the same way.
  • Test: user A deletes user B's media id via A's own campaign path returns 404.

R7. Public response still over-exposes

  • Where: getPublicCampaignBySlug
  • Problem: returns notesComments (private notes), campaign notes, amount, paymentStatus, and now creator email.
  • Fix: switch include to select. First grep client/src/components/admin/brandView/** for fields the brand UI renders. Remove notesComments, notes, and user.email always. Remove amount/paymentStatus only if the UI does not render them; if it does, keep and flag. Creator endpoints unchanged.
  • Also: move the Draft/Active to Under Review status change out of GET into POST /public/:shareToken/opened, called once by the brand page on mount.

R8. Stored XSS via other uploads (rest of C7)

  • Where: middlewares/upload.middleware.ts (avatar, brand logo, portfolio, CMS), app.ts
  • Problem: these still accept any image/* (SVG), extension comes from originalname, and /uploads has no nosniff/CSP.
  • Fix:
    1. Allow only jpg, jpeg, png, webp, gif, avif (no SVG) for avatars, logos, CMS. Portfolio also mp4, mov, webm. Extension on disk comes from the allowlist.
    2. After upload verify magic bytes with file-type for all upload types (including campaign); delete the file and return 400 on mismatch or unknown type. .txt has no signature: accept it only if the first 8 KB is valid UTF-8 with no NUL bytes. Reject everything not on the allowlist (owner decision: no SVG, no exceptions).
    3. Static /uploads: set X-Content-Type-Options: nosniff and Content-Security-Policy: default-src 'none'; sandbox; add Content-Disposition: attachment except for image/video/audio/pdf.
    4. Delete the stored file if a permission check fails after upload (e.g. updatePortfolioItem).
  • Test: upload x.svg as avatar returns 400.
